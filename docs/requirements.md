# kazkiueda.com 要件定義書（ドラフト）

## 1. 文書の目的

本書は `https://kazkiueda.com` の初期リリースおよびその後の運用に関する**プロダクト要件**と**非機能要件**を定義する。実装詳細（ルーティングの実装ファイル名等）は別紙の設計・実装プランに委ねる。

## 2. 背景とライフサイクル

- **当面の目的**: 転職活動。転職エージェントおよび応募先企業の面接担当者にポートフォリオを提示する。
- **中長期**: 転職活動終了後も、**個人のポートフォリオサイト**として継続し、**定期的に更新**する。一般向けの検索流入は狙わず、**URL を知っている相手のみ**の閲覧を想定する（**HTTP Basic 等のパスワードゲートはかけない** — 2026-04 合意。採用担当の体験優先）。

## 3. スコープ（URL とコンテンツ）

| パス                                | 要件                                                                                                                                |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `https://kazkiueda.com/`          | 初期は**サイト本体のコンテンツを置かない**。`**/portfolio` へのリダイレクト**とする。リダイレクトは**暫定**のため **HTTP 302 または 307**（恒久的 301 は将来 `/` に本格的なトップを置く可能性を考え避ける）。 |
| `https://kazkiueda.com/portfolio` | 初期フェーズで**唯一**用意するコンテンツ領域（ポートフォリオ）。転職後も同パスで継続更新。                                                                                   |

## 4. アクセス制御

- **方式（2026-04）**: **認証なし**。転職エージェント・採用担当には **HTTPS の URL のみ**を共有する。URL を知る第三者は閲覧できるため、**現職に関する記述の取り扱い**はコンテンツ側と運用（リンクの共有範囲）で管理する。
- **想定利用者**: 転職エージェント、応募先の面接対応者。
- **将来**: Cloudflare Access 等の追加ゲートは**別イテレーション**で検討可（本書の初期方針では必須としない）。

### 4.1 セキュリティ・運用

- **シークレット**: ポートフォリオ閲覧用の共有パスワードは**用いない**（旧 `PREVIEW_SECRET` / Basic は廃止）。
- **ログ**: 個人を特定しうる情報を**不必要にログに出さない**。
- **位置づけ**: 「URL を手掛かりにした**緩い閉域**」であり、**強い本人確認や機密保証ではない**。

## 5. 検索エンジン・AI クローラー

**明示的なクローラー向けシグナル**を多層で行う（完全排除は保証しないが、インデックスされにくくする）。現職に関する情報の外部露出を**できる限り抑える**。

- **`robots.txt`**: `/portfolio` を **`Disallow`**。主要 AI クローラ向け `User-agent` ブロック（例: `GPTBot`, `Google-Extended`）でも同パスを **`Disallow`**。
- **HTML**: `<meta name="robots" content="noindex, nofollow, noarchive">`（レイアウト共通）。
- **HTTP ヘッダ**: Cloudflare Pages の **`_headers`** で **`/portfolio`** および **`/portfolio/*`** に **`X-Robots-Tag: noindex, nofollow, noarchive`**（`meta` と値を一致させる）。
- **サイトマップ**: `/portfolio` を**含めない**（またはサイトマップ自体を出さない方針を維持する）。

## 6. ホスティング・アーキテクチャ

- **方針（2026-04）**: **Cloudflare Pages** に **静的ビルド成果物 `dist`** を載せる。GitHub Actions で `bun run build` のあと **`wrangler pages deploy ./dist`**。オンデマンド SSR / Worker 上のミドルウェア認証は**用いない**。
- **フロントエンド技術**: **Astro** を主とし、必要に応じて **SolidJS**（アイランド等）を用いる。

## 7. 受け入れ条件（例）

- ブラウザの **Basic 認証ダイアログが出ず**、**URL を開けば** `/portfolio` コンテンツが閲覧できる。
- `/` は `/portfolio` へ **302 または 307** でリダイレクトされる。
- `robots.txt`、HTML の **robots `meta`**、および **`X-Robots-Tag`**（導入時）が、本書セクション 5 の方針を満たす。

## 8. 実装プランに委ねる事項（TBD）

以下は本書では**確定せず**、Plan / 設計フェーズで決める。

- リダイレクトを **302 と 307 のどちらに固定するか**（GET のみなら 302 で十分なことが多い）。
- 追加の `User-agent` ブロックの一覧（ボットの変遷に合わせて更新）。

## 9. 合意履歴（要約）

| 論点           | 決定                                                    |
| ------------ | ----------------------------------------------------- |
| `/`          | 暫定で `/portfolio` へリダイレクト（302/307）                     |
| `/portfolio` | 継続・定期更新。**認証なし**（2026-04）                              |
| アクセス        | URL 共有のみ（Basic 廃止）                                    |
| 検索・AI        | `robots.txt` + `noindex,nofollow,noarchive`（meta + **`X-Robots-Tag`**） |
| ホスティング       | **Cloudflare Pages**（静的 `dist`）                        |
| スタック         | Astro、必要時 SolidJS                                     |
