# kazkiueda.com 要件定義書（ドラフト）

## 1. 文書の目的

本書は `https://kazkiueda.com` の初期リリースおよびその後の運用に関する**プロダクト要件**と**非機能要件**を定義する。実装詳細（ルーティングの実装ファイル名等）は別紙の設計・実装プランに委ねる。

## 2. 背景とライフサイクル

- **当面の目的**: 転職活動。転職エージェントおよび応募先企業の面接担当者にポートフォリオを提示する。
- **中長期**: 転職活動終了後も、**個人のポートフォリオサイト**として継続し、**定期的に更新**する。一般公開にはしない（非公開ゲートのまま）。

## 3. スコープ（URL とコンテンツ）


| パス                                | 要件                                                                                                                                |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `https://kazkiueda.com/`          | 初期は**サイト本体のコンテンツを置かない**。`**/portfolio` へのリダイレクト**とする。リダイレクトは**暫定**のため **HTTP 302 または 307**（恒久的 301 は将来 `/` に本格的なトップを置く可能性を考え避ける）。 |
| `https://kazkiueda.com/portfolio` | 初期フェーズで**唯一**用意するコンテンツ領域（ポートフォリオ）。転職後も同パスで継続更新。                                                                                   |


## 4. アクセス制御

- **方式**: **サイト全体で共有パスワード 1 つ**。指定したパスワードを転職エージェント・採用担当者に伝達する運用とする。
- **未認証時**: `/portfolio` の中身（静的 HTML 等）は**取得できない**こと。期待する HTTP 挙動（401、またはログイン用フォームを返す 200 等）は実装設計で定義する。
- **想定利用者**: 転職エージェント、応募先の面接対応者（メールアドレス事前ホワイトリストは運用負荷が高いため採用しない）。

### 4.1 セッション

- **パスワード入力後の「ログインが効く期間」**: **ブラウザセッション**（ブラウザを閉じたら再入力）。長期 `Max-Age` による「数日ログイン不要」は採用しない。

### 4.2 セキュリティ・運用（Cloudflare に準拠した記載）

- 共有シークレットは **リポジトリに含めず**、Cloudflare の **Secrets** 等で管理する。
- セッション Cookie は `**Secure`・`HttpOnly`**、適切な `**SameSite`** を付与する。
- **ブルートフォース対策**: パスワード試行に対する**レート制限**（実装は Worker 内または Cloudflare プラットフォーム機能）を行う。
- **ログ**: パスワード・セッション Cookie の**平文をログに出さない**。
- **位置づけ**: 本方式は**強い本人確認ではない**が、URL を知る第三者の**偶然の閲覧を防ぐ**ためのゲートとする。漏洩時はパスワード変更で対応する。

## 5. 検索エンジン・AI クローラー

認証レイヤーに加え、**明示的なクローラー向けシグナル**を多層で行う（完全排除は保証しないが、インデックスされにくくする）。

- `**robots.txt`**: `/portfolio` を `**Disallow`**。ルートの方針も文書化する。
- **認証後に返す HTML**: `<meta name="robots" content="noindex, nofollow">`。必要に応じて `**noarchive`** を検討する。
- **サイトマップ**: 初期は `/portfolio` を**含めない**（またはサイトマップ自体を出さない方針を設計で決める）。

## 6. ホスティング・アーキテクチャ

- **方針 A（採用）**: **Cloudflare Pages** にビルド成果物をデプロイし、**Pages Functions または別 Worker** で `/portfolio`（および `/` のリダイレクト）の**前段認証**を行う。
- **フロントエンド技術**: **Astro** を主とし、必要に応じて **SolidJS**（アイランド等）を用いる。

## 7. 受け入れ条件（例）

- 未認証で `/portfolio` にアクセスしたとき、仕様どおり認証が要求される。
- 正しいパスワード後のみポートフォリオコンテンツが閲覧できる。
- `/` は `/portfolio` へ **302 または 307** でリダイレクトされる。
- `robots.txt` および認証後 HTML の robots メタが、本書セクション 5 の方針を満たす。
- レート制限が有効であること（具体的閾値は設計で定義可）。

## 8. 実装プランに委ねる事項（TBD）

以下は本書では**確定せず**、Plan / 設計フェーズで決める。

- リダイレクトを **302 と 307 のどちらに固定するか**（GET のみなら 302 で十分なことが多い）。
- レート制限の閾値（分あたり試行回数等）。
- ログイン UI の文言言語（日本語のみか等）。
- Pages Functions と独立 Worker の**どちらでゲートするか**、およびプロジェクト構成（モノレポ等）。

## 9. 合意履歴（要約）


| 論点           | 決定                                                    |
| ------------ | ----------------------------------------------------- |
| `/`          | 暫定で `/portfolio` へリダイレクト（302/307）                     |
| `/portfolio` | 非公開のまま継続・定期更新                                         |
| 認証           | 共有パスワード 1 つ                                           |
| セッション        | ブラウザセッション                                             |
| 検索・AI        | `robots.txt` + `noindex,nofollow`（+ 必要なら `noarchive`） |
| ホスティング       | Cloudflare Pages + Functions/Worker ゲート               |
| スタック         | Astro、必要時 SolidJS                                     |
