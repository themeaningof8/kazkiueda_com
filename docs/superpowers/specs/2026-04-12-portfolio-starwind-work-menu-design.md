# Portfolio: Starwind ホバー「制作実績」メニュー + ヘッダーチップ削除

## 1. 目的

- 固定ヘッダー直下の **ケーススタディ横スクロールチップ帯**（旧称と混同しやすいが、**画面下端の dock ではない**）を **削除**し、ヘッダーの縦占有を減らす。
- **`md` 以上**のビューポートで、「制作実績」に **ポインタホバー**したときに **各ケーススタディへの導線**を表示する。
- UI は **[Starwind UI](https://starwind.dev/)** を用いる（Astro + 素の JS のコンポーネントを CLI で取り込む方式）。

## 2. 非目的（今回やらない）

- **`md` 未満**で「制作実績」やケース一覧を **新設しない**（現状どおり。ケースへはページ内スクロールやカード操作に依存）。
- 下端固定の **dock** の復活。
- 左レールナビの復活。

## 3. 背景と用語

- **dock**: 会話・旧プランで指していた **画面下端 `fixed` のチップ帯**。コードベースからは既に除去済み。
- **ヘッダーチップ帯**: `PortfolioTopNav` 内で `PortfolioCaseStudyNav` を描画していた **2 段目**。本仕様で **削除**する。

## 4. 推奨アーキテクチャ

### 4.1 Starwind の選定

- **Popover** を採用する。`openOnHover` と `closeDelay` でホバー表示と、トリガーからパネルへポインタを移す猶予を制御する（[Popover ドキュメント](https://starwind.dev/docs/components/popover/)）。
- トリガーの見た目に **Button** 等が必要なら、Starwind CLI で **`popover` に加え必要最小限のコンポーネント**を追加する。

### 4.2 ブレークポイント

- Popover ブロック（「制作実績」トリガー + パネル）は **`md`（768px）以上のみ** DOM に出す、または **`hidden md:block`** 等で **モバイルでは非表示**。既存のプライマリ `nav`（`hidden md:flex`）と同じ閾値に揃える。

### 4.3 `PortfolioTopNav`

- **`PortfolioCaseStudyNav` のインライン描画を削除**する（ヘッダー 2 段目のチップ帯なし）。
- `caseNavItems`（型は既存の `CaseStudyNavItem[]` を流用）は **Popover 内のリンク一覧**にだけ渡す。リネームは任意（実装時に可読性で判断）。

### 4.4 「制作実績」の情報設計

- **トリガー**: 見た目は現行のテキストナビに近い **ボタンまたはリンク**とし、**キーボード・スクリーンリーダーで開閉可能**にする（ホバーのみに依存しない）。
- **パネル内リンク**（推奨構成）:
  1. 先頭に **「制作実績セクションへ」** など、`workHref`（一覧では `#work`、詳細では `/portfolio#work`）への 1 本。
  2. 続けて **各ケース**（`href` は `CaseStudyNavItem` のルール: 既定 `#${anchorId}`、詳細ページでは `/portfolio#case-…`）。
- 単一の `<a href="#work">制作実績</a>` をそのまま残しつつホバーで別 UI を出すと **二重導線・フォーカス順**が複雑になるため、**トリガーは「メニューを開く」役**に寄せ、**#work への移動はパネル内の明示リンク**に任せる方針とする。

### 4.5 スクロール位置ハイライト（IntersectionObserver）

- 既存の `PortfolioCaseStudyNav.astro` 内スクリプト（`astro:page-load` で `a[data-case-anchor]` を収集）は **チップ帯がなくても**、Popover 内の各ケースリンクに **`data-case-anchor` とケース用のクラス／マークアップ規約**を揃えれば、**一覧ページ**では引き続き **現在セクションの強調**が可能。
- **実装方針（いずれかをプランで確定）**:
  - **A**: スクリプトを **`PortfolioCaseStudyNav` から `PortfolioTopNav` 用の小さな共有スクリプト／レイアウト**へ移し、Popover 内リンクだけを対象にする。
  - **B**: `PortfolioCaseStudyNav` を **マークアップなしのスクリプトのみ**残すか、スクリプトだけ別 `.ts` に切り出す。
- **詳細ページ**では対応する `id` が DOM に存在しないため、現状どおり **オブザーバは早期 return** でよい。

### 4.6 スタイルとトークン

- Popover パネルは **Sage トークン**（`portfolio.css` の `--color-*`）と **既存の角丸・境界線リズム**に合わせ、Starwind デフォルト色のまま置かない。
- `PopoverContent` の `side` / `align` / `sideOffset` は **ヘッダー下に被さらない**よう `side="bottom"` `align="start"` などから選定する。

## 5. 依存関係とリスク

- プロジェクトは **Tailwind CSS v4**（`@tailwindcss/vite`）。Starwind の **Getting Started** を参照し、**v4 との手順整合**を導入時に確認する。衝突（設定・プラグイン・パス）があれば **Starwind 推奨の構成を優先**し、差分を最小に抑える。
- 追加パッケージ（例: `tailwind-variants`, `tailwind-merge`）が Starwind によって入る場合は **用途をコメントまたは spec に一行記載**し、不要な重複依存を増やさない。

## 6. アクセシビリティ

- Popover の **キーボード操作**（Escape 閉じる等）を Starwind 実装に任つつ、**フォーカスがパネル内に入ったときの視認性**を確認する。
- パネルに **`aria-label`**（例: 「制作実績」）または見出し要素を付与する。
- **`prefers-reduced-motion`** がある場合は、Starwind が提供する抑止に追従できない場合のみ、プロジェクト側でアニメーション時間を下げる（要実装時確認）。

## 7. 検証

- `bun run check` / `bun run build` が成功すること。
- **`md` 未満**: Popover が表示されない、レイアウトが現状意図と矛盾しないこと。
- **`md` 以上**: ホバーでパネル表示、パネル内リンククリックで正しい URL・ハッシュへ遷移、`closeDelay` 中にパネルへポインタを移せること。
