# Portfolio Page (Calm 2-column) parity — design spec

**Status:** Approved in brainstorming (2026-04-13).  
**Scope:** Paper の `Portfolio Page (Calm 2-column)` に沿って `/portfolio` を再構成する。連絡・`mailto:` 導線は置かない。`/about` を新設する。

## 1. Goals

- `/portfolio` を **Paper のポートフォリオ一覧**に近い体験へ寄せる：**コンパクトヘッダ**、**「ケーススタディ」見出し**、**縦に積むケースカード**（カード内は **左画像・右テキスト** の2カラム）。
- **データ**は既存の `caseStudies` コレクションと `order` ソートを単一ソースとして維持する。
- **PC幅を最優先**にレイアウト・余白・タイポを合わせる。タブレット／モバイルは **破綻しない範囲**で単純化してよい。
- ケーススタディ詳細ページの **About リンク先を `/about` に統一**する（`/portfolio#about` は廃止）。
- 実装完了後、Paper と **少なくとも1回の差分確認→修正→再確認** を行う。

## 2. Non-goals

- 連絡先ブロック、`mailto:`、お問い合わせCTA、**いかなる「連絡」導線もサイト上に置かない**（ヘッダ・フッター・本文を含む）。
- 旧 `/portfolio` の **ヒーロー大見出し**、**長文の About セクション**、**PortfolioContact 相当のセクション**は **一覧ページには載せない**。
- タブレット／モバイルでの Paper **ピクセル完全一致**。
- CMS 化や Markdown 以外へのデータ移行。

## 3. Information architecture

| Route | Purpose |
|-------|---------|
| `/portfolio` | Paper 準拠の **一覧**：ヘッダ＋ケーススタディ見出し＋ケースカード列＋フッター（SNS等のみ）。 |
| `/about` | **今回スコープで新設**。短文の自己紹介ページ。**連絡先は載せない**。 |

## 4. UI structure (`/portfolio`)

### 4.1 Header

- **固定**（現行トップナビに相当するが Paper トーンに合わせて簡素化）。
- 左：**氏名**（例: 植田 一貴）と **「ポートフォリオ」** のラベル／サブライン（Paper の情報階層に合わせる）。
- 右：**`About` のみ** → **`/about`** へリンク。
- **下線（`border-b`）は付けない**（ケーススタディ詳細ヘッダと整合）。
- **削除するもの:** 「お問い合わせ」CTA、`mailto:`、`#contact` への導線、**`PortfolioWorkNavPopover`（制作実績ポップオーバー）およびケーススタディ一覧向けのアンカーナビ**（Paper の一覧ヘッダは **About のみ**に相当するため）。

### 4.2 Main

- コンテンツ **最大幅 ~1296px**、**横インセット ~72px**（1440 幅想定）を目安に、既存のスペーシングトークンで再現する。
- **セクション見出し:** 「ケーススタディ」（Paper の Work Intro に相当）。
- **ケースカード:** 各カードは **同型**で縦に積む（現行 `PortfolioCaseStudy` の **交互レイアウト（ジグザグ）は廃止**）。カード内は **左：画像**（`preset` に応じたアスペクト）、**右：ロールバッジ、タグ、タイトル、概要、アウトカム、詳細へのリンク** 等、既存データで埋まる要素を Paper の密度に合わせて配置する。

### 4.3 Footer

- コピーライト＋外部リンク（Instagram / LinkedIn / Dribbble 等）は **ENV があればリンク、なければ準備中表示** の既存パターンを維持できる。
- **メールアドレス表示・`mailto:` は置かない**。

## 5. `/about` page

- **新規ルート** `src/pages/about.astro`（またはプロジェクト規約に合うパス）。
- **内容:** 短文の自己紹介（既存 `PortfolioAbout` のコピーから **必要部分のみ** 転用してよいが、一覧に長文セクションを復活させない）。
- **連絡先セクションは置かない**。
- レイアウトは **`PortfolioLayout` ＋ 簡素なヘッダ**で統一するか、一覧と同系のシェルを使うかは実装計画で決める（本仕様では **一覧とヘッダ／フッターの一貫性**を要求する）。

## 6. Case study detail (`/portfolio/work/[slug]`)

- ヘッダ内 **`About` の `href` を `/about` に変更**する（`/portfolio#about` への依存をなくす）。
- それ以外の3カラム本文レイアウトは **本仕様の対象外**（既存のケーススタディ詳細仕様を維持）。

## 7. Data and behavior

- **一覧:** `getCollection('caseStudies')`、**昇順 `order`**、**`id` タイブレーク**は現行と同じ。
- **画像:** `getImage` による最適化と **`transition:name`**（一覧→詳細の共有要素）は維持する。
- **Prerender / robots:** 既存の `PortfolioLayout` 方針（`noindex` 等）を踏襲する。

## 8. Accessibility

- ページに **`h1` は1つ**。文言は「ポートフォリオ」またはサイトにふさわしい単一タイトルとし、**「ケーススタディ」は `h2`** とする（実装で微調整可だが、**複数 `h1` は禁止**）。
- カードがリンクの場合は **既存と同様**、リンクの accessible name を維持する。

## 9. Verification

- `bun run check` と `bun run build` が通る。
- PC 幅で Paper の **ヘッダ・見出し・カードの左画像／右テキスト比率**を確認し、**最低1回**の修正ループで差分を解消する。
- **連絡導線が残っていない**ことを grep またはレビューで確認する（`mailto:`、お問い合わせ文言、 `#contact`）。
