# 転職向けケーススタディ改善デザイン仕様（Brainstorming）

作成日: 2026-04-14  
対象: `/portfolio` 配下のケーススタディおよび `/about`  
作成者: Codex（Kazki との合意内容を反映）

## 1. 目的と背景

転職活動における主要読者（事業会社の採用担当・意思決定者）が、短時間で以下を判断できる状態を作る。

- 実装まで落とし切れる実行力がある
- 組織を動かす推進力がある
- 失敗や未解決課題を学びに変換できる成熟度がある

現状コンテンツは高品質だが、採用判断に必要な「定量感」「読み順に沿った情報設計」「人物像の一貫接続」が不足している。  
本仕様では、既存ケースを全面改稿せず、骨格を活かした差分編集で説得力を高める。

## 2. ターゲットと訴求軸

### 2.1 想定応募先

- 第一想定: 事業会社
- ポジションは現時点で広く保持（絞り込みはしない）

### 2.2 優先訴求

- 主軸1: 実装まで落とし切る実行力（デザインシステム〜FE）
- 主軸2: 組織を動かす推進力（ファシリテーション・越境）

### 2.3 表現方針

- 失敗・未解決は隠さず「学びとして明確に記述」する
- 見出し・本文は日本語主軸で統一する
- 定量は実数に限定せず、レンジや体感比率で記述する

## 3. 全体情報アーキテクチャ（4ケース構成）

ナンバリングは表示順と一致させる。

1. Case 01: デザインシステム構築
2. Case 02: AIを活用したページ制作知見（新規）
3. Case 03: Owners App UX施策提案
4. Case 04: スクラムマスター・意思決定設計

### 3.1 各ケースの役割

- Case 01: 実装力の再現可能性を証明する主軸
- Case 02: 2026時点でのAI活用実務力を提示する差別化軸
- Case 03: 課題再定義と提案力で上流対応力を補強
- Case 04: 難局推進と学習姿勢で信頼を締める

### 3.2 重複回避ルール

- Case 01は「恒常基盤（デザインシステム）」を扱う
- Case 02は「AI協業による高速制作運用」を扱う
- 両方が実装テーマでも、時間軸と価値を分離して記述する

## 4. 編集戦略（既存骨格を活かす差分編集）

### 4.1 編集の優先順

既存ケースは全面書き直しせず、以下を優先して差分修正する。

1. 冒頭Outcome（30秒要約）を明確化
2. 定量レンジ（2〜3指標）を追記
3. 未解決課題から次アクションへの接続を明記
4. 見出しを日本語へ統一

### 4.2 4ケース共通テンプレート

各ケースは以下の骨組みを保つ。

1. 成果要約（冒頭一文）
2. 変化量（定量レンジ）
3. どう実現したか（再現可能な手法）
4. うまくいかなかった点と学び（次の行動原則まで）

## 5. ケース別デザイン

## 5.1 Case 01（デザインシステム）

目的: 実装まで落とし切る主軸を最短で伝える。  
実施内容:

- 冒頭成果文を維持しつつ、定量レンジを追記
- 三層構造（リント／Tailwind／UIライブラリ）とトークンパイプラインの再現性を強調
- 「利用促進とリーダーシップが鍵」の学びを、運用設計の示唆として明文化

定量文の例（レンジ）:

- 導入前比で初期実装着手までの時間が体感30〜50%短縮
- 意匠解釈のすり合わせ時間が週次換算で約40%減少
- UI再実装コストが体感で半減

## 5.2 Case 02（新規: AIを活用したページ制作知見）

主題: 本ポートフォリオ制作をケース化し、社内AIイニシアチブへの接続を示す。  
見出し構成（日本語）:

1. 背景
2. 課題の再定義
3. AI協業の設計
4. 品質を守るためのガードレール
5. 成果
6. 社内への展開（AIイニシアチブ）
7. 学びと今後

必須要素:

- AIに任せた範囲と、人間が最終判断した範囲の分離
- 品質担保基準（情報設計、A11y、トーン整合、レビュー導線）
- 社内展開の具体（テンプレート化、レビュー規約、再利用単位）

定量文の例（レンジ）:

- 情報設計〜初稿作成のリードタイムを約40〜60%短縮
- 修正反映サイクル時間を体感で半分以下に圧縮
- 最終公開文面は人間編集責任を維持（AIは草案生成に限定）

## 5.3 Case 03（Owners App UX施策提案）

目的: 上流の課題再定義と合意形成の実務力を補強。  
実施内容:

- 「受注」だけでなく、刺さった理由（提案の順序・言葉・意思決定の整理）を明記
- AI活用タグと本文記述の整合を保持
- 実現可能性を評価された理由を、判断材料ベースで明文化

定量文の例（レンジ）:

- AI一次分析により約101万件データを約1週間でペルソナ/CJM化
- 提案討議の収束速度が体感で約30%向上

## 5.4 Case 04（スクラムマスター・意思決定設計）

目的: 未解決を含む実務経験を、信頼獲得の材料へ変換。  
実施内容:

- 「短期モメンタム止まり」を隠さず記述
- ただし終わり方を弱くせず、学び→運用改善原則へ接続
- 完了見通し説明の不足を明文化し、次に何を変えたかを示す

定量文の例（レンジ）:

- 未決会議比率を体感30〜40%低減
- 同論点の再帰を目に見えて減少
- 一方、見通し説明不足により期限優先収束が発生（反省点）

## 6. About連携デザイン

目的: ケースの成果と人物像の接続を一本化する。  
方針:

- About冒頭を以下の軸に整合:
  - 「実装で前進させ、意思決定で停滞をほどくデザイナー」
- ケースの読後にAboutへ遷移しても、同じ人物像として認識される語彙を採用

## 7. OGPサマリー設計

採用担当がSlack/LinkedInでURL共有した際に、要点が即時理解できることを目標とする。

### 7.1 サマリー文の型

- 誰が（役割）
- 何を変えたか（成果）
- どれくらい変えたか（レンジ）

### 7.2 実装示唆

- ケースページ単位で `title / description / og:image` の出し分けを将来実装する
- 本仕様段階では文面設計を優先し、画像設計は次フェーズで扱う

## 8. 非機能・トーン制約

- 日本語主軸、落ち着き・信頼・テキスト主導（CLAUDE.md準拠）
- 誇張表現を避け、根拠を伴うレンジ記述を優先
- 守秘義務に配慮し、公開可能情報のみで因果を説明

## 9. 受け入れ基準（デザイン完了定義）

- 4ケースの役割が重複なく説明できる
- 各ケース冒頭に成果要約があり、2〜3個の定量レンジを含む
- 失敗/未解決の記述が学びと次アクションへ接続される
- 見出し言語が日本語統一である
- About冒頭文がケース群と同一軸で接続される
- OGPサマリー文の型が各ケースに適用可能な状態である

## 10. スコープ外

- 実装コード変更（本仕様はBrainstorming成果物）
- OGP画像の具体制作
- 応募先別に複数バージョンの完全分岐運用
